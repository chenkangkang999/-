# 医疗问诊多智能体协作系统 — 需求与技术方案（最终版）

> 答辩项目 · 从零搭建 · 本文档为开发的唯一依据

---

## 一、项目定位

基于 **协调器（Coordinator）+ 多专职 Agent** 的医疗问诊协作系统，覆盖「问诊 → 检索 → 用药 → 风险评估 → 辩论仲裁 → 白话解释 → 安全护栏」全链路，并配套监控面板与计费体系。

---

## 二、功能清单

### 1. 多智能体体系（7 个 Agent + 辩论机制）

| Agent         | 核心功能                                                         |
| ------------- | ------------------------------------------------------------ |
| 问诊 Agent      | 多轮追问、症状标准化（ICD-11/SNOMED CT）、疑似诊断排序（Top-N+概率）、红旗征识别、病种问诊模板   |
| 检索 Agent      | RAG（Milvus 全量索引）、混合检索（BGE 稠密 + BM25 稀疏）、重排序、证据摘要、引用溯源        |
| 用药 Agent      | 用药推荐（一线/二线）、相互作用检查、禁忌筛查、特殊人群剂量调整、不良反应预警、用药教育                 |
| 风险评估 Agent    | 紧急程度分级（低/中/高/极高）、红旗征筛查、慢病风险预测（Framingham）、就医路径推荐、生命体征预警      |
| 白话解释 Agent 🆕 | 医学结论 → 大白话：SOAP 小结 + 通俗解释 + 就医指引（普通人能听懂）                     |
| 安全护栏 Agent 🆕 | 合规审核（规则引擎 + LLM 双判）：拦截越界用药建议并映射到具体监管条款、强制标注「不替代医生」、极高风险自动转急诊 |
| 诊断辩论机制 🆕     | 多 Agent 意见分歧时互相质证、收敛，提升准确率（LangGraph 编排）                     |

### 2. 协调器与协作流程

- 意图识别、任务分发、结果汇总、冲突仲裁
- 调度顺序：问诊 → 检索 → (风险评估 ∥ 用药) → 辩论/仲裁 → 白话解释 → 安全护栏 → 最终回复（含溯源引用）
- 仲裁规则：**极高风险 > 禁忌覆盖 > 证据支持**（检索只提供证据，不决策）

### 3. RAG 检索工程

- Milvus 全量索引（所有医学文档切片入库）
- BGE-M3 embedding（**LoRA 微调**，微调前后做 Recall@K 对比实验）
- 混合检索（BGE 稠密向量 + BM25 稀疏向量融合）
- 重排序（LLM / Cross-encoder）
- **hash 索引去重**（索引前对文档算内容 hash，重复文档跳过）
- RAG 评估：Recall@K / MRR / NDCG

### 4. 数据工程

- LangChain 历史对话管理（多轮上下文）
- 各 Agent 埋点，采集监控面板所需数据
- 用户 👍/👎 反馈采集（数据飞轮源头）

### 5. Web 应用

- **Django 后端**：REST API、用户认证、计费、WebSocket 流式回复
- **Vue3 前端**：问诊页、Agent 协作面板（实时调用状态）、各 Agent 详情测试页、监控面板

### 6. 监控面板

| 分类     | 指标                                  |
| ------ | ----------------------------------- |
| 检索性能   | 平均 latency、p99 latency、召回失败率（无 hit） |
| 索引规模   | chunks 总数、去重后的文档数、最近一次索引时间          |
| LLM 成本 | 按 query / 按用户 / 按时间分组               |
| 质量信号   | 用户 👍/👎 反馈率                        |
| 失败模式   | 超时 / 限流 / 解析失败 / 预算溢出               |

### 7. 计费功能

- token 计费（input / output 分开计价）
- 按用户 / 按查询生成账单
- 每用户每日预算 cap（防超支）

### 8. 缓存与异步

- Redis：检索结果缓存、LLM 响应缓存、会话存储、限流（token bucket）、Celery 队列 broker

## 三、技术方案

| 层次    | 选型                                                                               |
| ----- | -------------------------------------------------------------------------------- |
| 后端    | Django + DRF + Django Channels（WebSocket）                                        |
| 前端    | Vue3 + Vite + Pinia + Vue Router + ECharts + Element Plus                        |
| 业务库   | PostgreSQL                                                                       |
| 缓存/队列 | Redis + Celery                                                                   |
| 向量库   | Milvus（开发用 Milvus Lite，正式 Docker）                                                |
| 多智能体  | 自定义 BaseAgent / AgentCoordinator + **LangGraph**（辩论编排）+ **LangChain**（历史对话）      |
| RAG   | Milvus + BGE-M3（LoRA 微调）+ BM25 稀疏 + rerank + hash 去重（**不用 LangChain**）           |
| LLM   | deepseek-API（OpenAI 兼容，可换 Qwen/GLM），每 Agent 独立 system prompt，`_execute()` 为唯一替换点 |
| 计费    | tiktoken 统计 token，input/output 分别计价                                              |
| 部署    | Docker Compose（Django + Vue3 + Redis + Milvus + PostgreSQL）                      |

## 八、安全护栏双判与监管条款库

**双判机制**：规则引擎（本地代码，毫秒级，不依赖 API）+ LLM 语义兜底（deepseek-API）。

**监管条款库（草案，需对照官方最新原文核准条文号）**：

| 触发场景      | 映射条款                         | 动作                  |
| --------- | ---------------------------- | ------------------- |
| AI 直接开具处方 | 《互联网诊疗监管细则（试行）》：严禁 AI 自动生成处方 | 拦截 + 提示处方须由接诊医师本人开具 |
| 首诊患者要求诊断  | 《互联网诊疗管理办法（试行）》：互联网诊疗主要针对复诊  | 拦截 + 引导线下首诊         |
| 越界用药建议    | 《处方管理办法》《药品管理法》              | 拦截 + 提示就医           |
| 极高风险      | —                            | 直接转 120/急诊          |

拦截输出结构化：`{ 拦截, 原因, 监管条款, 严重程度 }`
